# 结果、限制与工程边界

## 1. 功能验证结果

- 建立 79 项 SystemC 测试点，覆盖准入、调度、Mesh、返回路径、burst、存储、错误边界、reset 和压力场景；
- 已实现 58 项测试点，P0 核心项完成 42/43；
- directed case 固定关键语义，stress case 检查多 master、多 target、hotspot 和反压下的组合行为；
- 阶段性 VCS/URG 回归中，功能覆盖率为 73.96%，covergroup instance score 为 85.11%。

上述结果表示核心事务链路已形成工程验证闭环，不表示穷尽所有输入组合，也不构成形式化完备性证明。

## 2. 性能优化结果

通过移除 phase 之间的人为排空、拆分读/计算/写线程、增加本地 buffer 和 FIFO，最慢 PEA 完成周期由 53585 降至 47411，减少 6174 周期，约 11.5%。

性能分析区分三类数据：

1. 有效读写和计算服务量构成的理想下界；
2. 加入启动、有限槽位、Mesh 调度和排空后的事务账本；
3. 当前实现的实际回归周期。

固定回归周期用于发现行为变化，不被表述为脱离仿真的理论预测。

## 3. 并发度结论

当前架构在高压力场景下验证了多个在途事务配置。安全配置可以完成回归并最终清空；继续增加在途事务会出现循环等待风险。这说明优化方向应是拆分请求/返回资源依赖或引入可证明无死锁的通道，而不是只扩大 outstanding 常数。

## 4. 低功耗结构优化

Golden Owner 由宽自由运行计数器及除模逻辑改为最小位宽的窗口计数器和 owner 计数器。8×6 网络中相关状态寄存器由 1536 bit 降至 432 bit。该数字只代表寄存器位数变化；最终动态功耗仍需在相同工艺、约束和活动率下通过综合与功耗分析确认。

## 5. 尚未公开或尚待完善

- 完整业务 workload、地址映射和周期级内部接口；
- 商业 VIP 下的完整 UVM 环境及覆盖率数据库；
- reset、错误注入以及低覆盖 condition/FSM/toggle 的进一步补强；
- 同一工艺与活动率条件下的优化前后 PPA 定量比较。
